Do código ao grafo

Um laço while em dez linhas, anotado passo a passo: por que cada linha vira líder, onde os blocos começam e terminam, e como os sucessores são decididos.

  • 1 primeira instrução do programa
  • 2 alvo de desvio (label)
  • 3 logo depois de um desvio

O código de três endereços

Cada linha é uma instrução com no máximo três endereços. L1, L2 e L4 são labels: nomes de posições usados como alvo de desvio.

1i = 0
2L1:
3if i < 10 goto L2
4goto L4
5L2:
6t = a + b
7i = i + 1
8goto L1
9L4:
10x = t

Passo 1 · marcar os líderes

Um bloco sempre começa em um líder. As linhas destacadas abaixo são líderes; o rótulo à direita diz qual regra se aplicou.

1i = 0regra 1 · primeira instrução
2L1:regra 2 · label / alvo
3if i < 10 goto L2
4goto L4regra 3 · após o if
5L2:regra 2 · label / alvo
6t = a + bregra 3 · após goto L4
7i = i + 1
8goto L1
9L4:regra 2 · label / alvo
10x = tregra 3 · após goto L1

Duas confusões comuns. Na linha 8, goto L1 é um desvio, mas não é líder: a regra 3 fala da instrução que vem depois de um desvio. Quem é líder por causa dele é x = t, na linha 10. E quando um label e a instrução seguinte ocupam a mesma posição — L2 e t = a + b — existe um líder, não dois.

Passo 2 · cortar nos líderes

O bloco vai do seu líder até a linha anterior ao próximo líder. O label vira o cabeçalho do bloco: ele marca a posição, mas não é uma instrução que se executa.

B0linha 1
i = 0
B1linhas 2–3
L1:
if i < 10 goto L2
B2linha 4
goto L4
B3linhas 5–8
L2:
t = a + b
i = i + 1
goto L1
B4linhas 9–10
L4:
x = t

Passo 3 · olhar a última instrução

Para achar os sucessores, só a última instrução do bloco importa. O que acontece no meio já está resolvido dentro do próprio bloco.

BlocoÚltima instruçãoSucessoresPor quê
B0i = 0B1não termina em desvio: segue para o próximo bloco
B1if i < 10 goto L2B3, B2alvo do desvio (L2) + fall-through
B2goto L4B4desvio incondicional
B3goto L1B1desvio incondicional: aresta de retorno
B4x = t—fim do fluxo, nenhum sucessor

A saída do TDE2

Com os sucessores calculados, a saída para o arquivo fica assim. A ordem dos números dentro de { } não importa — o enunciado aceita pequenas variações.

saida.txt
Bloco 0: succs { 1 }
Bloco 1: succs { 3 2 }
Bloco 2: succs { 4 }
Bloco 3: succs { 1 }
Bloco 4: succs { }

Casos que quebram a cabeça

  • Dois labels seguidos. O segundo também é líder, então pode nascer um bloco vazio entre eles. Decida se imprime e documente.
  • if como última instrução do arquivo. Não existe fall-through: o bloco tem um sucessor só, o alvo do desvio.
  • Label no fim, sem instrução. É um bloco vazio. O mesmo vale para o label inicial sozinho.
  • Desvio para label inexistente. Trate como erro do arquivo de entrada, não como um bloco 0 silencioso.
  • Fim de bloco sem desvio. Cai no bloco seguinte, que é justamente o próximo líder.
Os nomes B0…B4 são didáticos. No seu parser, o ID do bloco pode ser o número do label (<bb 4>) ou uma numeração sequencial — o que não pode faltar é o mapa label → bloco para resolver os alvos dos desvios.
